# В OpenGOAL Compiler

В OpenGOAL (проекте по декомпиляции игр Jak) действительно есть как компилятор, так и интерпретатор, и они тесно связаны. Компилятор использует интерпретатор для обработки **макросов**, написанных на языке GOOS.

### 🧠 Зачем компилятору интерпретатор?

Компилятор GOAL (`goalc`) написан на C++ и отвечает за превращение исходного кода в машинный код x86-64. Однако в языке GOAL есть мощная система макросов, которые пишутся на отдельном языке — **GOOS**.

GOOS — это макроязык, который выполняется во время компиляции. Компилятор не может просто «скомпилировать» макрос, потому что макрос должен **сначала выполниться**, чтобы сгенерировать код на GOAL, который затем уже будет компилироваться.

Для этого внутри компилятора встроен интерпретатор GOOS. Когда компилятор встречает макрос, он передаёт его в этот интерпретатор, получает результат (новый код на GOAL) и продолжает компиляцию уже с ним.

### 🎯 Как компилятор различает команды?

Всё очень просто: **различие определяется тем, как выглядит форма (S-выражение)**.

1.  Компилятор читает файл и получает список S-выражений (например, `(defun foo ...)`).
2.  Когда он видит форму, он смотрит на её «голову» (первый элемент списка).
3.  Если «голова» — это **символ, который зарегистрирован как макрос GOOS**, компилятор понимает: «Ага, это макрос!». Он вызывает интерпретатор GOOS, передаёт ему аргументы, получает результат и затем компилирует этот результат как обычный код GOAL.
4.  Если «голова» — это **встроенная форма компилятора** (например, `defun`, `if`, `+`), или **обычная функция GOAL**, компилятор обрабатывает её сам, генерируя промежуточное представление (IR) и, в конечном итоге, машинный код.

То есть, компилятор не «отдаёт команды» интерпретатору. Он сам решает, что текущая форма — это макрос, и запускает интерпретатор для его раскрытия.

### ⌨️ Основные команды консоли управления

Управление происходит через REPL (Read-Eval-Print Loop). При запуске вы видите приглашение `g >` (или `gc>` при подключении к игре). Вот основные команды, которые вводятся прямо в этой консоли:

| Команда | Синтаксис | Описание |
| :--- | :--- | :--- |
| **Сборка игры** | `(mi)` | **M**ake **I**SO. Запускает полную сборку игры (инкрементально). |
| **Компиляция файла** | `(asm-file "путь/к/файлу.gc" :color :load)` | Компилирует `.gc` файл. Флаги: `:color` (генерация кода), `:load` (загрузить в игру), `:write` (сохранить `.o` файл). |
| **Подключение к игре** | `(lt)` | **L**isten to **T**arget. Подключается к запущенной игре (по умолчанию `127.0.0.1:8112`). После этого приглашение меняется на `gc>`. |
| **Перезапуск** | `(reload)` | Сбрасывает состояние компилятора, как будто вы его только что запустили. |
| **Выход** | `(e)` или `(:exit)` | Выход из компилятора. Если есть подключение к игре, попытается сбросить её. |
| **Информация** | `(get-info <символ>)` | Показывает, чем является символ (функция, константа, форма) и где он определён. |
| **Автодополнение** | `(autocomplete <префикс>)` | Показывает все символы, начинающиеся с указанного префикса. |
| **Запуск GOOS** | `(seval <форма>)` | Выполняет код на GOOS напрямую. Используется для побочных эффектов, результат не возвращается. |

Если запустить компилятор с флагом `-c`, он выполнит одну команду и выйдет. Без флагов он запускает полноценный REPL, где можно вводить эти команды.

В итоге: **компилятор управляет всем процессом, а интерпретатор GOOS — это его вспомогательный инструмент для выполнения макросов во время компиляции.**
